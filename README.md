# Job Market Observer

Сервис для регулярного сбора вакансий, нормализации данных и анализа спроса на
технологии. Проект использует документированный публичный API HeadHunter вместо
HTML-скрейпинга, сохраняет историю изменений в PostgreSQL и отдаёт аналитику через
FastAPI.

## Что показывает проект

- периодический ETL-процесс на APScheduler с защитой от параллельных запусков;
- HTTP-клиент официального HH API с явным `User-Agent`, паузой между страницами,
  таймаутами и повторными запросами при `429`/`5xx`;
- нормализацию грейдов, названий навыков и зарплат в рубли (для известных курсов);
- PostgreSQL, SQLAlchemy 2 и версионирование схемы через Alembic;
- идемпотентную загрузку по `(source, source_id)` и SHA-256 значимых полей;
- историю изменений вакансии без одинаковых снимков;
- статистику по городам, грейдам, технологиям и новым вакансиям по дням;
- REST API, Swagger/OpenAPI и небольшой дашборд с графиком;
- unit-тесты парсинга на сохранённом ответе API и интеграционный тест дедупликации;
- Docker Compose и CI-проверки в GitHub Actions.

## Архитектура

```text
HH public API
     │
     ▼
HeadHunterClient ── retries / rate limiting
     │
     ▼
normalization ── grade / salary / skills
     │
     ▼
ingestion ── upsert + content hash
     │
     ├── vacancies (актуальное состояние)
     ├── vacancy_snapshots (история изменений)
     ├── skills + vacancy_skills (нормализованный справочник)
     └── collection_runs (аудит запусков)
                  │
                  ▼
          FastAPI + dashboard
```

Такое разделение позволяет заменить источник данных, правила нормализации или
интерфейс независимо друг от друга.

## Быстрый запуск

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Для своих параметров поиска скопируйте `.env.example` в `.env`. Без этого шага
Docker Compose запустится с безопасными локальными значениями по умолчанию.

После старта доступны:

- дашборд: <http://localhost:8000/>;
- интерактивная документация: <http://localhost:8000/docs>;
- health check: <http://localhost:8000/health>.

Сервис `migrate` один раз применяет миграции, после чего независимо запускаются API
и планировщик. `scheduler` сразу выполняет первый сбор, затем повторяет его с интервалом
`COLLECT_INTERVAL_MINUTES`. Параметр `HH_AREA=113` означает Россию. Для портфолио
обязательно замените контакт в `APP_USER_AGENT` на свой: это хороший тон при работе
с публичными API.

## Локальная разработка

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
alembic upgrade head
job-market-collect --text "python" --area 113 --pages 3
uvicorn job_market.api:app --reload
```

Конфигурация берётся только из переменных окружения; пароли и адреса БД в коде не
хранятся. Для ручного запуска PostgreSQL можно использовать только сервис `db`:

```bash
docker compose up -d db
```

## REST API

| Метод | URL | Назначение |
|---|---|---|
| `GET` | `/api/v1/vacancies` | вакансии с пагинацией и фильтрами `city`, `grade`, `skill`, `active` |
| `GET` | `/api/v1/stats/cities` | распределение по городам |
| `GET` | `/api/v1/stats/grades` | распределение по грейдам |
| `GET` | `/api/v1/stats/technologies` | наиболее востребованные навыки |
| `GET` | `/api/v1/stats/demand/history?days=30` | число впервые замеченных вакансий по дням |
| `GET` | `/health` | доступность приложения и БД |

Пример:

```bash
curl "http://localhost:8000/api/v1/vacancies?city=Москва&grade=senior&skill=python"
```

## Модель истории и защита от дублей

Одна запись в `vacancies` соответствует внешнему ID вакансии. При каждом сборе
сервис вычисляет хеш только из значимых полей: заголовка, работодателя, города,
опыта, занятости, зарплаты, навыков и архивного статуса.

- новый внешний ID создаёт вакансию и первый снимок;
- тот же ID и тот же хеш обновляют только `last_seen_at`;
- тот же ID с новым хешем обновляет актуальное состояние и добавляет снимок;
- ограничения БД остаются последней линией защиты при конкурентных запросах.

Исходный JSON также сохраняется для повторной обработки, отладки и эволюции правил
нормализации.

## Нормализация

Навыки очищаются, приводятся к нижнему регистру, дедублируются и проходят через
словарь алиасов (`Postgres → postgresql`, `K8s → kubernetes`). Грейд извлекается из
названия, а при его отсутствии оценивается по требуемому опыту.

Суммы хранятся одновременно в исходной валюте и в нормализованных полях
`salary_rub_from/to`. Рубли конвертируются с коэффициентом `1`; для других валют
нормализатор принимает явный словарь курсов и не подставляет вымышленные значения,
если курс неизвестен.

## Проверки качества

```bash
pytest --cov=job_market --cov-report=term-missing
ruff check .
```

Тесты не обращаются к интернету и не зависят от текущей разметки сайта. Сохранённый
JSON в `tests/fixtures` выступает контрактным примером ответа источника.
